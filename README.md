# nox

A Nostr client with no server. One codebase ships three ways:

| Target | Built from | Shell |
|---|---|---|
| Web | `src/` | Vite, deployed to Cloudflare Workers at nox.garden |
| Desktop (Windows, macOS, Linux) | `src/` | Tauri 2, wrapping `dist/` as-is |
| Android and iOS | `native/` + `src/common/` | Expo (React Native) |

Protocol, cache and judgement live in `src/common` and are shared by every
target. The web and desktop UI is `src/`; the phone UI is `native/`.

## Prerequisites

- Node.js 20+ and Bun. Three lockfiles are checked in; use `bun install` to
  install and `npm run <script>` to run scripts.
- Desktop: the [Tauri 2 prerequisites](https://v2.tauri.app/start/prerequisites/)
  for your OS.
- Android: JDK 21 and the Android SDK, with `ANDROID_HOME` set. On WSL, see
  the note under "Phone" about adb.
- iOS: macOS with Xcode.

## Web

```bash
bun install
npm run dev        # http://localhost:3000
npm run build      # type-checks, then writes dist/
npm run preview    # serves dist/
```

Deploying is `npm run deploy` from a maintainer machine that is logged in to
Wrangler. Pull requests get a Netlify preview at
`deploy-preview-<n>--nox-preview.netlify.app`.

## Desktop

```bash
npm run tauri:dev      # runs the Vite dev server inside a Tauri window
npm run tauri:build    # installers under src-tauri/target/release/bundle/
```

The Tauri Android build (`npm run android:dev`, `npm run android:build`) is
the older phone path and is being replaced by the Expo app below. Signing
and release steps for it are in `docs/android-release.md`; the iOS CI build
is in `docs/ios-testflight.md`.

## Phone (Expo)

The app is a separate package under `native/` with its own dependencies.

```bash
cd native
bun install
npm run android    # builds and runs on the connected device or emulator
npm run ios        # macOS only
npm run start      # Metro alone, for a dev client already installed
```

`native/android/` and `native/ios/` are generated by `expo prebuild` and are
not in git. They are created on the first run. After changing anything in
`native/app.json` that affects the generated project - intent filters, the
package name, permissions - delete `native/android` (or run
`npx expo prebuild --platform android --no-install` in `native/`) before the
next build, or the previous manifest ships.

On WSL2, USB devices are not visible to Linux. `npm run device` in `native/`
builds a release APK and installs it through the Windows `adb`; it expects the
Android SDK under the Windows user's `AppData\Local\Android\Sdk` and a JDK at
`~/.local/jdk-21`. Adjust `native/run-device.sh` if yours differ.

App Links (`https://nox.garden/npub1…` opening the app) need the association
files served by the web deploy; `docs/app-links.md` explains both halves and
how to check a device's verdict.

## Checks

```bash
npm test           # Node's test runner over tests/, compiled to .tmp/test-dist
npm run check      # Biome: lint and format
npm run format:write
```

For the phone app, type-check with `npx tsc --noEmit -p tsconfig.json` in
`native/`. The shared modules under `src/common` are covered by `npm test`
from the repository root.

## Where things are

```text
src/app/        entry, routing, global state (web and desktop)
src/common/     protocol, cache, sessions, relays - shared by every target
src/features/   one directory per screen (web and desktop)
native/         the Expo app: App.tsx, screens/, components/, lib/, platform/
src-tauri/      the desktop shell
public/         static files copied into dist/, including .well-known/
docs/           release, App Links, privacy policy, terms
tests/          shared-module tests
```

`AGENTS.md` (also read as `CLAUDE.md`) carries the architecture notes and the
conventions for changes; read it before working on the code.
